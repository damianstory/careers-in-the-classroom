# Robots & Pencils

CGY-204-FULL v1 · 2026-10-23

## Classroom question

How does a team decide whether an app solves the problem it was built for?

## Company and Calgary connection

Robots & Pencils combines software engineering, design and strategy. Its services include clarifying use cases and assessing the data and operating conditions needed for an application.

The company lists Calgary among its locations. Its published service descriptions apply across the organization.

## How it works

1. Describe the task a user is trying to complete.
2. Translate the need into a small, observable requirement.
3. Build a prototype and test ordinary and exceptional inputs.
4. Use observations to revise the requirement or implementation.

## Classroom activity

Prototype a fictional school equipment-booking screen. Define success as showing only available items and explaining rejected requests. Have a partner try an unavailable item, a missing return date and a valid request. Separate a programming bug from a requirement that was unclear.

**Discuss:** When a user cannot complete a task, how would you decide whether the problem is the code, the interface or the requirement?

**Limits:** The school-booking task is an editorial teaching example, not a named client project. The company name does not establish physical robotics work. No private client data or claimed productivity result is used.

## Course connection

CSE1120 · Structured Programming 2: selected outcomes 1, 1.9, 2, 3.1. Requirements, decision rules and tests. The company activity is an editorial application.
